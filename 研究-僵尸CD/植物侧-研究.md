### 1.3 显示口径（已实现）

| 状态 | 文本 | 颜色 | 判据 |
|---|---|---|---|
| 未叠种 | `叠种 1/2` | `BusyColor`（青蓝，暗示"还能再叠一株"） | `_stacks == 0` 且 `num < 75` |
| 已叠种 | `叠种 2/2 · 产出 75` | `ReadyColor`（绿） | `_stacks >= 1` 或 `num >= 75` |

- 与 ⑩「等级型植物」的 `等级 N/M` 同格式、同思路（`Entry.cs` ⑩ 段：增压大喷菇 `等级 n/4`、豆荚壳 `等级 n/3`；它们靠 `LevelSet(int)` 识别，而**毁灭向日葵没有 `LevelSet`** ⇒ 必须单独识别，这就是本分支存在的理由）。
- **两路取数互为兜底**：`_stacks` 走反射（`FindFieldAlong`，沿类型链找，兼容未来派生变体）；`ProduceComponent.num` 走公开属性（`cm.GetRuntime<ProduceComponent>("character.produce")`）。两路都拿不到 ⇒ 不出行（不猜、不显示假数值）。
- **分类开关**：`CatOn(8)`（等级与加速）**或** `CatOn(7)`（战斗辅助）任一开启即显示。
  · 归 (8) 的理由：⑩ 段把「叠种升级型」（增压大喷菇 / 豆荚壳）放在「等级与加速」，毁灭向日葵的叠种是同语义；
  · 也接受 (7)：Lead / cdmod-owner 建议归「战斗辅助」；两者默认都开，OR 起来玩家最不容易"看不到"。
- 与既有通道**不重复**：②.9 产出分支显示的是「阳光 X.Xs」（产出倒计时，`produceType` 非 Coin/Packet 都归"阳光"），本行显示的是「档位」，语义不同。

### 1.5.2 破损机制（**真实只有 2 道裂纹**，不是 3）

`DamagePoint\MagicStoneNutDamagePointData.tres` 里只有 3 个 damage point：

| damage point | `damagePersontage` | 替换贴图 | 含义 |
|---|---|---|---|
| `Damage0` | `1.0` | `MagicStoneNut_body.png` | **完好**（不是"破损 1 级"） |
| `Damage1` | `0.6666666667` | `MagicStoneNut_cracked1.png` | 第 1 道裂纹 |
| `Damage2` | `0.3333333333` | `MagicStoneNut_cracked2.png` | 第 2 道裂纹 |

推进逻辑（`TowerDefenseCharacterInstance.cs`）：

| 行 | 内容 |
|---|---|
| `:117` | `public int damagePointIndex;` —— **已触发的 damage point 个数**（0..3） |
| `:1400` | `double num3 = (hitpoints - hitpointsNearDeath) / (hitpointsSave - hitpointsNearDeath);` |
| `:1403` | `while (damagePointIndex < _damagePointPercentages.Length && num3 <= _damagePointPercentages[damagePointIndex])` |
| `:1405/1426/1428` | 取名字 → `SetDamageStage(damagePointIndex)` → **`damagePointIndex++`** |
| `:1995-1998` | 读档时：`num = Math.Min(damagePointIndex, damagePoints.Count)`，且 `damagePoints[0].Persontage >= 1.0` 时 `num = 1`（⇒ Damage0 是"基线"，不视作破损） |
| `:2033 / :2087` | `damagePointIndex` 参与存档 `ExportSave` / `ImportSave` |

`TowerDefensePlantMagicStoneNut.cs` 里另有：`:28-41 ApplyDamagePointState()` 把 `Damage0/1/2` 映射成 `customData` 的 `Custom0` 值 `0/1/2`（"有破损表现"的判据）；`:43-50 OnCustomSwitched()` 用 `hitpoints / hitpointsSave` 调 `PreviewDamagePoint(...)`；`:19-26 DamagePointReach()` 每次受击 `CastHaste()`；`:7-9 HasteTime=5.0 / HasteTimeScale=3.0`（**加速 buff，不是破损次数**）。

### 1.5.3 显示口径（已实现）

```
stage = instance.damagePointIndex（首选，public 字段）
      ↑ 读不到时兜底：用同一公式复算（读 config.damagePointData.damagePointList[i].damagePersontage）
cracks = clamp(stage - 1, 0, 2)          // Damage0 = 完好 ⇒ 裂纹 = 阶段 - 1
文本   = "破损 N/2"                        // N = 0 绿(完好) / 1~2 青蓝
```

| `damagePointIndex` | 实际外观 | 显示 |
|---|---|---|
| 0（没受击） | 完好 | `破损 0/2` |
| 1（只触发 Damage0） | 完好（body.png） | `破损 0/2` |
| 2（Damage1） | cracked1 | `破损 1/2` |
| 3（Damage2） | cracked2 | `破损 2/2` |

- **为什么不是 Lead 最初写的 `N/3`**：3 个 damage point 里 `Damage0` 是**完好**档（`damagePersontage = 1.0`、贴图 `MagicStoneNut_body.png`），真正会碎的是 `Damage1`/`Damage2` 两级。若按 `N/3` 显示，会出现"刚被打一下但外观完好却显示破损 1/3"的错位。若 Lead 更想要"阶段 0~3"口径，改一个常量即可（`MagicStoneNutMaxCracks` 与 `stage` 的映射）。
- **分类开关**：`CatOn(7)`（战斗辅助）**或** `CatOn(8)`（等级与加速）任一开启 —— 破损阶段既非计时也非等级，玩家最可能在「战斗辅助」找；沿用与「叠种」一致的 OR 口径。
- **不重复加「加速 5.0s」**：`CastHaste()`（`:62-97`）加的是 `TowerDefenseCharacterBuffCoffee{ key="MagicStoneNutHaste", timeScaleValue=3.0, time=5.0 }`，而 CD Mod 既有 ⑨ 段已按 buff 的 `timeScaleValue` 显示「加速 +N%」（`Entry.cs:3168-3172` / `:3424`）⇒ 那 5 秒加速本来就会显示，再加一行是重复，也会碰到已定稿的加速通道。

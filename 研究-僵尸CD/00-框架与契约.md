## 1. 扩展点：精确签名（以源码为准）

`mods\HealthCooldownLine\runtime_src\HealthCooldownLineEntry.cs` 里已声明（**你只写实现，不要改声明**）：

```csharp
partial void CollectZombieCdLinesA(ComponentManager cm, TowerDefenseCharacter character,
    string charName, System.Collections.Generic.List<(string Text, Color Color, double Total)> lines);   // → ZombieCdA.cs（a）

partial void CollectZombieCdLinesB(ComponentManager cm, TowerDefenseCharacter character,
    string charName, System.Collections.Generic.List<(string Text, Color Color, double Total)> lines);   // → ZombieCdB.cs（b）
```

调用现场（唯一调用点，`TryCollectInfo` 末尾）：

```csharp
TryCollectZombieCdLines(cm, character, charName, lines);   // 门控全在这里
```

`TryCollectZombieCdLines` 的**不变量**（可以当保证用）：

| # | 保证 |
|---|---|
| 1 | `character` 是**「僵尸类」或「骨堆类」**：绝大多数是 `TowerDefenseZombie` 子类；**唯一例外**是 `TowerDefenseSkeleton`（骷髅伽刚特尔的 30 秒复活骨堆，`TowerDefenseSkeleton : TowerDefenseGravestone : TowerDefenseCharacter`，**不是僵尸**）⇒ **不要**无条件 `(TowerDefenseZombie)character` 强转，身份判定用 `charName` / `character.GetType().Name` |
| 2 | 进到这里时 **总开关 `_enabled` = true 且 `_showZombieCd`（显示僵尸冷却）= true** |
| 3 | `cm != null`、`lines != null`、`lines.Count < MaxTotalLines(6)` |
| 4 | 你抛的异常会被 `TryCollectZombieCdLines` 兜住（A/B 各一个「只报一次」标志），但**你自己也要整体 try/catch**，否则一个僵尸出错会让同批后面的僵尸全跳过 |
| 5 | A、B 两批互相独立：`CollectZombieCdLinesA` 抛异常不影响 B |

**为什么是 partial 方法**：类已经 `sealed partial`，虚函数没有落点；`partial void` 是零成本抽象 ——
**没写实现时编译器直接删掉调用点**，所以「a 写完、b 还没动工」这种中间状态也能编译通过（反之亦然）。
⚠️ 实现方法**必须**加 `partial` 关键字且**不能**加访问修饰符（`partial void` 隐含 private）。

类声明行（两个文件都照抄这一行，**不要再写基类列表**）：

```csharp
public sealed partial class HealthCooldownLineEntry
```

### 2.1 我新加的僵尸专用助手（推荐直接用，别再自己写一份反射）

```csharp
static FieldInfo ZombieField(Type t, string name);   // 沿类型链找字段 + 按「类型全名|字段名」缓存；找不到返回 null
static double    ZombieNum(object obj, FieldInfo f, double fallback);   // 读 double，取不到/类型不符返回 fallback，绝不抛
static bool      ZombieFlag(object obj, FieldInfo f);                   // 读 bool，取不到返回 false
static bool      IsZombieChar(TowerDefenseCharacter c);                 // 是否 TowerDefenseZombie（框架内部也在用）
static bool      ZombieNameIs(string charName, params string[] names);  // charName 精确匹配（区分大小写）
static bool      ZombieCdDisplayable(double remaining, double total);   // remaining>0 && total>0
```

用法（这就是推荐写法，**反射取字段，不 cast 到具体僵尸类**）：

```csharp
partial void CollectZombieCdLinesA(ComponentManager cm, TowerDefenseCharacter character,
    string charName, System.Collections.Generic.List<(string Text, Color Color, double Total)> lines)
{
    try
    {
        if (!ZombieNameIs(charName, "ZombieNormalDoomShroom")) { return; }   // 不是我的僵尸 ⇒ 直接走

        Type t = character.GetType();
        FieldInfo fTimer = ZombieField(t, "timer");   // 已走过 = 已累计秒数
        FieldInfo fTime  = ZombieField(t, "time");    // 总秒数（25~30 随机）
        FieldInfo fBoom  = ZombieField(t, "explode"); // 是否已进入爆炸动画
        if (fTimer == null || fTime == null) { return; }

        double elapsed = ZombieNum(character, fTimer, 0.0);
        double total   = ZombieNum(character, fTime, 0.0);
        if (ZombieFlag(character, fBoom)) { return; }        // 已经在爆了，别再倒数
        double remain = total - elapsed;
        if (!ZombieCdDisplayable(remain, total)) { return; }
        if (lines.Count >= MaxTotalLines) { return; }

        AddTimer(lines, "爆破 " + remain.ToString("0.0") + "s", BusyColor, total);
    }
    catch { }
}
```

## 3. 僵尸身份怎么拿（**两个名字别搞混**）

| 名字 | 来源 | 例子 | 用途 |
|---|---|---|---|
| `charName`（框架已传入） | `character.config.name`（= `CharacterResource.json` 的键） | `ZombieNormalDoomShroom` | **首选判据**（配置键最稳定） |
| 类名 | `character.GetType().Name` | `TowerDefenseZombieNormalDoomShroom` | 兜底判据（配置键缺失/一个类多僵尸时用） |

判据写法建议（**双通道**，与你研究的证据表一一对应）：

```csharp
bool IsMine = ZombieNameIs(charName, "ZombieNormalDoomShroom")
           || (charName == null && character.GetType().Name.IndexOf("DoomShroom", StringComparison.Ordinal) >= 0);
```

**强类型能不能用？** 能，`TowerDefenseZombie` / `TowerDefenseCharacter` 都是 `public partial class`（`unpack\Prefab\TowerDefense\Character\TowerDefenseZombie.cs:3`），

**但不要** cast 到具体僵尸类（那些类在 `unpack\Asset\Anime\Character\Zombie\**\*.cs`，虽然也在同一个 DLL 里，但一旦某类被改名/设成 internal 就是**编译期硬失败**，把整包带崩）。
⇒ **具体僵尸一律走反射（`ZombieField`/`ZombieNum`），基类才允许 cast。**

## 4. 数据从哪来：三条通道（照你的研究对象选，选错就显示不出来）

### 通道 ①：僵尸类自己的字段（**31 个里大多数走这条**）
- 位置：`unpack\Asset\Anime\Character\Zombie\<章>\<组>\Scene\<名字>\TowerDefenseZombie<Xxx>.cs`
- 特征：计时在 `BatchUpdate(double delta)` 里累加，典型写法 `timer += delta * timeScale;`，然后 `if (timer < time) return;`
- ⇒ **剩余 = `time`(总) − `timer`(已过)**；字段多半是 `public`，但也可能 `private` ⇒ 用 `ZombieField` 沿类型链找
- 例（已实读，见 §6）

### 通道 ②：`CharacterTimerComponent`（挂了 TimerComponentDefinition 的那批）
- 取法：`CharacterTimerComponent t = cm.GetRuntime<CharacterTimerComponent>("character.timer");`
- 三个字段**按计时器名字典化**：`timerRunning : Dictionary<string,bool>` / `timerWaitTime : Dictionary<string,double>` / `timerCurrent : Dictionary<string,double>`
- 语义：`current` 从 0 递增（=已过）；**剩余 = wait − current**
- 反射字段名：`timerRunning` / `timerWaitTime` / `timerCurrent`（`Entry.cs` 里 `_fTimerRun`/`_fTimerWait`/`_fTimerCur` 已经缓存好，但那是 private 静态字段，**你用 `ZombieField(typeof(CharacterTimerComponent), "timerWaitTime")` 自己取更直观**）

### 通道 ③：组件（`cm.GetRuntime<T>(instanceId)`）
- `cm.GetRuntime<T>(instanceId)` / 有 `FindComponentOfType<T>(cm)`（同文件里有）
- 已确认的 InstanceId 常量（Entry.cs 顶部）：`character.cannon` / `character.timer` / `character.potato` / `character.bowling` / `character.catapult` / `character.chomper` / `character.grow_up` / `character.magnet` / `character.produce` / `character.tanglekelp` / `character.gravebuster`
- 僵尸自己的组件实例 id 用 `InstanceIdKeysDump(cm)` 可打印全部 key（诊断用）

⚠️ **通用通道已经会显示的东西不要重复显示**：加农炮装填、`character.timer` 的命名计时器、生成计时等，`TryCollectInfo` 前半段已经处理。
你的分支只负责**这些僵尸独有的**动作 CD；如果某僵尸唯一的计时就是 `character.timer` 里的某个 key，那它**可能已经被通用通道显示**了 ⇒ 先确认，别写重复行。

## 5. 显示规范（跟现有风格一致，用户看惯的样子）

### 5.1 文本格式

```
<标签><空格><剩余秒数, 1 位小数>s        ← 计时行（AddTimer）
<标签><空格>就绪 / 已开启 / 生效中        ← 状态行（AddLine，用 ReadyColor）
```

- 秒数**一律** `rem.ToString("0.0") + "s"`（1 位小数，与「装填 12.4s」「消化 20.0s」一致）
- 标签 ≤4 个汉字，**动词/名词**，不要带括号
- 多段 CD ⇒ **每个 CD 一行**（多行由 ShowLines 自动向上排，颜色可不同）

### 5.3 颜色

- 冷却中/倒计时中 ⇒ `BusyColor`（青蓝）
- 就绪/已生效/已充满 ⇒ `ReadyColor`（绿）
- 失效/不可用/数量为 0 ⇒ `DisabledColor`（灰）

### 5.4 「只显示 ≥5 秒」过滤（重要）

`AddTimer(..., total)` 的 `total` 会被 `只显示 ≥5 秒` 开关用：**`total < 4.9` 的整行从头到尾都不显示**。

- 能拿到稳定总时长 ⇒ 传真实值（例：毁灭菇 25~30、磁力 6~12）
- **总时长是动态的/取不到**（例：天使 `spawnTimer` 有时重置成 15 有时重置成 3）⇒ **传 `0`**，表示"不参与过滤，宁可显示也不误藏"
- 纯状态行（就绪/已开启）用 `AddLine`，天然不参与过滤

### 5.5 行数

`MaxTotalLines = 6` 是**该角色总共**的行数上限（Label 数组只有 6 个）。
⇒ 每个僵尸**建议 ≤2 行**，追加前判 `lines.Count < MaxTotalLines`（我已在入口判过一次，但你在循环里连加多行时要自己再判）。

## 6. 可显示性判据 + 「不可显示」怎么登记

**判据（写进你的研究 md，也写进代码注释）**：

| 情况 | 结论 |
|---|---|
| 能读到「剩余时间」+「总时长」 | ✅ **可显示**（`AddTimer`） |
| 只能读到「剩余时间」/「已过 vs 上限」但无稳定总时长 | ✅ 可显示，`total` 传 `0` |
| 只有布尔状态（开/关、有/无） | ✅ 可显示**状态行**（`AddLine` + Ready/Disabled 色），不做倒计时 |
| 只有静态配置值（间隔常量），运行时没有计时变量 | ❌ **不可显示**（"没有计时就没有倒计时可显示"，不要用配置值假装倒计时） |
| 能力是事件触发、瞬时完成（无持续时间） | ❌ **不可显示** |
| 该僵尸唯一的计时已被通用通道（②命名计时器/①加农炮）显示 | ⚠️ **不重复写**，在研究 md 里注明"已由通用通道显示" |

**「不可显示」的登记方式（两个都要做）**：

1. 研究 md 里一行：`中文名 / 类名 / 判据行（文件:行号）/ 结论=不可显示 / 原因`
2. 代码里留注释（便于以后有人问"为什么这个僵尸没有"）：

```csharp
// ── 不可显示：<中文名>（<类名>）
//   证据：<文件>:<行> —— <只读到一个静态间隔常量 / 能力是瞬发无持续 / 计时已被通用通道 ② 显示>
//   结论：不写分支（若将来该僵尸加了计时字段，在这里补分支即可）
```

## 10. v1.2 新增：**图鉴静态 CD 通道**（v1.27.0）

### 11.1 为什么需要一条独立通道（实读证据）

| 位置 | 有什么 | 能不能显示运行时 CD |
|---|---|---|
| 图鉴**格子** `AlmanacZombieWidow`（`AlmanacZombieWidow.cs:8`） | 只有 `AdobeAnimateSprite`：`Init(config)`（`:51`）→ `CreateSprite()`（`:83`）+ `FreezePreviewTree()`（`:114`） | ❌ 没有 `TowerDefenseCharacter` / 没有 Component / 没有 timer |
| 图鉴**详情面板** `InformationPanel`（`InformationPanel.cs:6`） | **会实例化真角色**：`chacraterScene.Instantiate()`（`:149`）→ `currentCharcter`（`:150`）→ `inGame = false`（`:159`）、`SetMainStateMachineDispatchEnabled(false)`（`:165`）、`spriteNode.AddChild(...)`（`:162`） | ❌ 角色在树里、**我们的扫描确实能扫到它**，但没有战斗循环 ⇒ 计时器永不推进 ⇒ 读"剩余"得到的是假值（多为 0 或初始值） |

⇒ 结论：**图鉴侧只能显示「配置里的满 CD 总时长」**，且必须与战斗内的"剩余"分成两条通道，文案上要能区分（本 Mod 统一加前缀 **`满CD：`**）。

> 附带事实（用户"图鉴看不到 CD"的直接观感来源之一）：`InformationPanel` 自带的「冷却时间」那行读的是
> `packetConfig.characterConfig.packetCooldown`（基类默认 **5.0**，`TowerDefenseCharacterConfig.cs:83`），
> 僵尸配置基本不覆盖该字段 ⇒ 图鉴里僵尸恒显示一个无意义的 `5.0`。它**不是**技能 CD。

### 11.2 扩展点（签名已落在 `HealthCooldownLineEntry.cs`）

### 11.3 写法约定（照抄，别自创）

```csharp
partial void CollectAlmanacStaticCdA(string charName, string saveKey,
    System.Collections.Generic.List<(string Text, Color Color, double Total)> lines)
{
    if (lines == null) { return; }
    if (ZombieNameIs(charName, "ZombieAngel"))
    {
        AddLine(lines, "复活 15.0s", ReadyColor);   // 静态值：一律 AddLine（Total=0）
        AddLine(lines, "无敌 8.0s", ReadyColor);    // 多段就多行（最多 3 行，我统一用「  ·  」连成一行）
        return;
    }
}
```

| 约定 | 结论 |
|---|---|
| 写入方法 | **`AddLine`**（`Total=0` ⇒ **不参与**「只显示 ≥5 秒」过滤）。**不要**用 `AddTimer` |
| 颜色 | 静态值一律 **`ReadyColor`**（绿） |
| 文案 | `<语义标签> <总时长>s`，与战斗内同词同序；**固定值 1 位小数**（`施法 12.0s`）；**随机值写区间**（`爆破 25~30s`、`自爆 9~20s`、`磁力 6~12s`） |
| 前缀 | **不要**自己写「满CD：」——外壳统一加，避免出现两个前缀 |
| 行数 | **最多 3 行**（`AlmanacMaxRows`），按重要性从高到低 `AddLine`，超出按顺序截断（外壳也会封顶，双保险） |
| 取哪个值 | **写有效值**：定义值被代码 `Run(key, x)` 覆盖的，写运行时实际用的那个（如唤魔使 `Cast` 定义 10.0 但 `Run("Cast",5.0)` ⇒ 写 **5.0**；飞行器 `Spawn` 定义 25.0 但每轮 `Run("Spawn",15.0)` ⇒ 写 **15.0**），并在注释里注明"定义 X / 有效 Y" |
| 门控 | **分支里不判开关**。外层 `TickAlmanacCd` 已判 `_enabled && _showAlmanacCd`（新开关「图鉴显示冷却」，默认开） |
| 异常 | 外层对 A / B / 植物三处分别 try/catch，各有"只报一次"标志 |

### 11.4 与「显示僵尸冷却」的关系

| 开关 | 管哪个面 | 默认 |
|---|---|---|
| 总开关 `enabled` | 全部（最高优先级） | 开 |
| 「显示僵尸冷却」`showZombieCd` | **战斗内**僵尸附加行 | 开 |
| 「图鉴显示冷却」`showAlmanacCd` | **图鉴/详情面板**的静态「满CD」行 | 开 |

三者**互相独立**（战斗里关掉僵尸 CD，图鉴仍可查满 CD；反之亦然），只有总开关能一键全灭。

### 11.5 战斗内的预览角色必须跳过运行时行

`ApplyToCharacter` 里新增：`if (!character.inGame) { HideAllLines(character); return; }`
—— `InformationPanel` 面板里那个预览角色 `inGame=false`，计时器不推进，运行时行只会显示"假倒计时"。
